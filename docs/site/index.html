Install and run

Linux x86-64

set -eu
asset=lcovmerge-1.0.2-linux-x86_64.tar.gz; base=https://github.com/megasoft1978/lcovmerge/releases/download/v1.0.2; curl -fL "$base/$asset" -o "$asset"; curl -fL "$base/SHA256SUMS" -o SHA256SUMS
awk -v name="$asset" '$2 == name { count++; print } END { if (count != 1) exit 1 }' SHA256SUMS > "$asset.sha256" && sha256sum -c "$asset.sha256" && tar -xzf "$asset"

Other OS: releases and checksums.

Merge then report

# The shell expands this pattern; lcovmerge does not.
lcovmerge coverage/shard-*.info -o coverage/merged.info
genhtml coverage/merged.info --output-directory coverage/html

Not for you if

  • Your report accepts every shard.
  • You need raw .gcda or .profraw data; export LCOV first.
  • Your lcov -a merge is fast enough.

Limits

  • --mem-limit limits memory reserved for coverage records while sorting; total process memory can be higher. Sorting needs temporary disk.
  • Not a drop-in for lcov -a: record policies can differ. Compare records and reports before switching.
  • Windows is verified in GitHub-hosted windows-latest CI: both MSYS2 UCRT64 GCC and the shipped Zig binary pass the full suite and smoke tests. Generated-input benchmarks run; CI has no LCOV comparator. Other Windows versions, physical desktops, and real-user reports remain unverified; large-dataset CI timings are disk-bound.
