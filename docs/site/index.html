A small step in your pipeline

Merge once, then carry on with the report command you already use.

01 Install · Linux x86-64

set -eu
asset=lcovmerge-1.0.2-linux-x86_64.tar.gz; base=https://github.com/megasoft1978/lcovmerge/releases/download/v1.0.2; curl -fL "$base/$asset" -o "$asset"; curl -fL "$base/SHA256SUMS" -o SHA256SUMS
awk -v name="$asset" '$2 == name { count++; print } END { if (count != 1) exit 1 }' SHA256SUMS > "$asset.sha256" && sha256sum -c "$asset.sha256" && tar -xzf "$asset"

Other OS: releases and checksums.

02 Merge, then report

# The shell expands this pattern; lcovmerge does not.
lcovmerge coverage/shard-*.info -o coverage/merged.info
genhtml coverage/merged.info --output-directory coverage/html

Built for this handoff

  • Your test jobs produce separate LCOV files.
  • Your report tool expects one combined file.
  • You want to keep the rest of your pipeline.

Know the edges

  • Input must already be LCOV; raw .gcda and .profraw are not collected. lcov -a may already be fast enough.
  • It does not create reports. It is not a drop-in for lcov -a; compare records and reports before switching.
  • --mem-limit bounds record memory during sorting; process memory can be higher and temporary disk is required.
