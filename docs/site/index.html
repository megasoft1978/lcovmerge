Quick merge

Merge, then keep your report step.

lcovmerge coverage/shard-*.info -o coverage/merged.info
genhtml coverage/merged.info --output-directory coverage/html

The memory setting limits memory reserved for coverage records while sorting. Total process memory can be higher, and sorting uses temporary disk. Read the limits.

Where it fits

Add one merge after LCOV export.

  1. CollectKeep your coverage tool.
  2. Export .info filesOne file from each test job.
  3. MergeCombine them with lcovmerge.
  4. Report or uploadUse the one LCOV output.

Use lcovmerge when separate .info files must become one output. Skip it if your report tool accepts each shard; export raw coverage first. It is not a drop-in for lcov -a; compare your records and reports before switching.

Why use it

A focused step for existing LCOV files.

Set a record-memory limit

Choose memory reserved for coverage records. Total process memory can be higher; sorted batches use temporary disk.

Keep output order stable

The same inputs, options, and build produce the same bytes across shard order and worker settings; this does not promise byte-for-byte identity with LCOV.

Use one C11 program

The merge job does not need a Node.js or Java runtime.

Install

Choose your operating system.

Release archives include SHA256SUMS. Each command verifies the archive and checks the installed version.

Linux · x86-64

For Linux ARM64, choose its matching archive from the release page.

set -eu
asset=lcovmerge-1.0.1-linux-x86_64.tar.gz
base=https://github.com/megasoft1978/lcovmerge/releases/download/v1.0.1
curl -fL "$base/$asset" -o "$asset"
curl -fL "$base/SHA256SUMS" -o SHA256SUMS
grep " $asset$" SHA256SUMS | sha256sum -c -
tar -xzf "$asset"
./lcovmerge --version

macOS · Apple silicon or Intel

set -eu
base=https://github.com/megasoft1978/lcovmerge/releases/download/v1.0.1
case "$(uname -m)" in
  arm64|aarch64) asset=lcovmerge-1.0.1-macos-arm64.tar.gz ;;
  x86_64|amd64) asset=lcovmerge-1.0.1-macos-x86_64.tar.gz ;;
  *) echo "Unsupported Mac architecture: $(uname -m)" >&2; exit 1 ;;
esac
curl -fL "$base/$asset" -o "$asset"
curl -fL "$base/SHA256SUMS" -o SHA256SUMS
grep " $asset$" SHA256SUMS | shasum -a 256 -c -
tar -xzf "$asset"
./lcovmerge --version

Windows · not yet verified on a Windows host

The release archive is available, but runtime behavior still needs a Windows host run.

$asset = "lcovmerge-1.0.1-windows-x86_64.zip"
$base = "https://github.com/megasoft1978/lcovmerge/releases/download/v1.0.1"
Invoke-WebRequest "$base/$asset" -OutFile $asset
Invoke-WebRequest "$base/SHA256SUMS" -OutFile SHA256SUMS
$entry = Get-Content SHA256SUMS | Where-Object { ($_ -split '\s+', 2)[1].TrimStart('*') -eq $asset }
if (@($entry).Count -ne 1) { throw "Expected one checksum entry for $asset" }
$expected = ($entry -split '\s+', 2)[0].ToLowerInvariant()
$actual = (Get-FileHash -Algorithm SHA256 $asset).Hash.ToLowerInvariant()
if ($actual -ne $expected) { throw "SHA256 checksum mismatch" }
Expand-Archive $asset -DestinationPath .\lcovmerge
.\lcovmerge\lcovmerge.exe --version

Other paths: Homebrew, Scoop, Docker, build from source, and GitHub Actions.

FAQ

Before you switch.

Does this replace lcov -a?

No. lcovmerge is not a drop-in replacement for lcov -a; compare your report and record needs before switching. See the migration guide.

What does the memory setting limit?

Memory reserved for coverage records only. Total process memory can be higher, and sorting uses temporary disk. Read all limits.

Can I pass raw coverage profiles?

No. Export LCOV .info files first; lcovmerge does not collect coverage or generate reports.
