Why this exists

LCOV files can be modest on disk and huge in memory.

Merging often means loading many records into object-heavy maps before writing the output. Large test suites and single-file reports have both exposed memory pressure in common coverage pipelines.

Large tracefiles have caused real CI failures.

Bazel’s CoverageOutputGenerator issue describes high memory use while processing large LCOV reports. Mozilla has also reported its code coverage aggregation task being killed under memory pressure.

Bazel issue #26383 ↗ Mozilla bug 2070106 ↗

GitHub Actions

Download the shard artifacts in a merge job, then run the CLI. Install or extract lcovmerge in an earlier step.

- uses: actions/download-artifact@v8
  with:
    pattern: coverage-*
    path: coverage-shards
    merge-multiple: true
- run: lcovmerge coverage-shards/*.info -o coverage/merged.info

Use a list file with @file if your shell argument list is too long. See the sharded workflow example.

Limits and compatibility

Know what the merger guarantees.

MC/DC is not a claim

lcovmerge does not claim MC/DC accounting semantics. If MC/DC interpretation matters to your reports, keep the lcov or compiler-toolchain workflow that defines and validates that data.

It complements lcov

lcov is a wider Perl tool for collecting and processing coverage data; it also merges tracefiles with --add-tracefile. lcovmerge focuses on merging LCOV inputs with a memory budget. It does not capture coverage from compiler artifacts or generate HTML reports.

Platform checks

Linux runtime behavior was exercised locally in Docker. The CI workflow includes Linux and Windows jobs; Windows runtime verification is pending a passing Windows CI run. The benchmark figures shown here were measured on macOS and do not establish cross-platform performance.

Package managers

Homebrew and Scoop package availability is not confirmed here. Use the release archives until a package manifest is published.

FAQ

A few practical details.

Does lcovmerge replace lcov?

No. It handles LCOV tracefile merging. lcov also captures coverage, filters and extracts tracefiles, summarizes data and supports other coverage workflows. Both tools can merge LCOV tracefiles; see the lcov manual ↗.

Can I feed it coverage shards from CI?

Yes. Pass the shard paths directly, or use @listfile for a long input list. A merge job can combine artifacts after test shards finish. See the GitHub Actions example.

Does it merge MC/DC coverage?

No MC/DC semantic guarantee is made. The published scope covers line, function and optional branch data. Check the current CLI documentation and your compiler and lcov versions before relying on other records.

Where are benchmark inputs and commands?

The benchmark page explains the synthetic inputs, host, run counts, caveats and reproduction procedure. The operating-system cache state was not controlled.
