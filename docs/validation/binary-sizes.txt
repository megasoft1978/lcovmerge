After sizes were measured from two identical `scripts/build-all.sh` builds. All five passed the size
check; `scripts/build-all.sh` now enforces the limit directly. The Windows size reduction is 18.9%.
A separate clean-cache build also passed its repeat-build check; its Mach-O outputs were 105016 bytes
(arm64) and 66451 bytes (x86-64), while Linux and Windows sizes matched the table. `otool -l` showed
the Mach-O size difference in `__LINKEDIT` data. The table records the paired same-cache build results.

Performance check on macOS 27 arm64, 1,118,686,233 input bytes, used `bench/run.py` with
`--workload M --skip-lcov --hyperfine-runs 5`, `--binary` set to each build artifact, and reports under
`.luna-tmp`.
The `-O2` release binary measured 280.5 MB/s before and 287.0 MB/s after; the two macOS binaries have
identical SHA-256, so the 2.3% difference is run variation. A separate macOS arm64 `-Oz` trial measured
295.2 MB/s (+5.2% against the first `-O2` median). The final build applies `-Oz` only to the Zig Windows
target; native Windows throughput was not measured.
