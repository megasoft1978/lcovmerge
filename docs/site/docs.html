First run

Turn exported LCOV files into one.

An LCOV .info file is a text file written by a coverage exporter. lcovmerge combines those existing files; it does not collect coverage.

Your first merge in three steps

  1. Download and extract

    Get lcovmerge v1.0.2 for your operating system. Verify the archive with its checksum before extraction. Windows runtime verification is pending.

    Choose an operating system and verify the archive ↓

  2. Merge the exported shards

    Run this from the directory that contains coverage/. The shell expands the wildcard.

    lcovmerge coverage/shard-*.info -o coverage/merged.info

  3. Keep your report or upload step

    The output is still an LCOV .info file.

    genhtml coverage/merged.info --output-directory coverage/html

Download and verify a binary

Choose the archive that matches your system and verify it before extraction. The Windows archive is available; runtime verification on a Windows host is pending.

Linux · x86-64

For Linux ARM64, choose its matching archive from the release page.

set -eu
asset=lcovmerge-1.0.2-linux-x86_64.tar.gz
base=https://github.com/megasoft1978/lcovmerge/releases/download/v1.0.2
curl -fL "$base/$asset" -o "$asset"
curl -fL "$base/SHA256SUMS" -o SHA256SUMS
entry=$(awk -v file="$asset" '$2 == file || $2 == "*" file { if (found++) exit 1; line=$0 } END { if (found != 1) exit 1; print line }' SHA256SUMS)
printf '%s\n' "$entry" | sha256sum -c -
tar -xzf "$asset"
./lcovmerge --version

macOS · Apple silicon or Intel

set -eu
base=https://github.com/megasoft1978/lcovmerge/releases/download/v1.0.2
case "$(uname -m)" in
  arm64|aarch64) asset=lcovmerge-1.0.2-macos-arm64.tar.gz ;;
  x86_64|amd64) asset=lcovmerge-1.0.2-macos-x86_64.tar.gz ;;
  *) echo "Unsupported Mac architecture: $(uname -m)" >&2; exit 1 ;;
esac
curl -fL "$base/$asset" -o "$asset"
curl -fL "$base/SHA256SUMS" -o SHA256SUMS
entry=$(awk -v file="$asset" '$2 == file || $2 == "*" file { if (found++) exit 1; line=$0 } END { if (found != 1) exit 1; print line }' SHA256SUMS)
printf '%s\n' "$entry" | shasum -a 256 -c -
tar -xzf "$asset"
./lcovmerge --version

Windows · runtime verification pending

The archive is available, but has not been runtime-verified on a Windows host.

$asset = "lcovmerge-1.0.2-windows-x86_64.zip"
$base = "https://github.com/megasoft1978/lcovmerge/releases/download/v1.0.2"
Invoke-WebRequest "$base/$asset" -OutFile $asset
Invoke-WebRequest "$base/SHA256SUMS" -OutFile SHA256SUMS
$entry = Get-Content SHA256SUMS | Where-Object { ($_ -split '\s+', 2)[1].TrimStart('*') -eq $asset }
if (@($entry).Count -ne 1) { throw "Expected one checksum entry for $asset" }
$expected = ($entry -split '\s+', 2)[0].ToLowerInvariant()
$actual = (Get-FileHash -Algorithm SHA256 $asset).Hash.ToLowerInvariant()
if ($actual -ne $expected) { throw "SHA256 checksum mismatch" }
Expand-Archive $asset -DestinationPath .\lcovmerge
.\lcovmerge\lcovmerge.exe --version

Try a no-install sample

Save the downloaded binary as lcovmerge in your current directory, then paste this in a POSIX shell. It creates two synthetic files and runs the binary from the parent directory; it does not install anything on your PATH.

mkdir -p .lcovmerge-demo
cd .lcovmerge-demo
printf '%s\n' 'SF:src/example.c' 'DA:1,2' 'end_of_record' > shard-a.info
printf '%s\n' 'SF:src/example.c' 'DA:1,3' 'end_of_record' > shard-b.info
../lcovmerge shard-a.info shard-b.info -o merged.info
cat merged.info

Expected output:

SF:src/example.c
DA:1,5
FNF:0
FNH:0
BRF:0
BRH:0
MCF:0
MCH:0
LF:1
LH:1
end_of_record

If the first run fails

Common first-run errors and the next check
ErrorTry this
Exit 1 · option or command errorRun lcovmerge --help; check the option spelling and that -o FILE is present.
Exit 2 · parse error with a line numberOpen the named input at that line and confirm it is an exported LCOV .info file, not a raw profile.
No input matchedCheck that the files exist under the current directory and match the wildcard. Use find coverage -name '*.info' or list paths in @coverage-files.txt.
Exit 3 · --tmpdir is not writableChoose an existing directory you can write to, and check that it has free disk space.
Exit 3 · output or temporary-file errorCheck write access and free space for both the output directory and the temporary directory.

See the full exit-status reference for all return codes.

Constrained CI example

This example budgets record memory and puts sorted temporary files in a directory created for this run:

set -eu
sort_dir=$(mktemp -d)
trap 'rm -rf "$sort_dir"' EXIT
lcovmerge --mem-limit 256M --tmpdir "$sort_dir" coverage/shard-*.info -o coverage/merged.info
genhtml coverage/merged.info --output-directory coverage/html

--mem-limit 256M is a coverage-record storage budget, not a total process RSS cap. Sorting needs free disk space in the selected temporary directory.

Check compatibility before switching

lcovmerge writes LCOV, but its output is not byte-identical to lcov -a and it is not a drop-in replacement. Run it beside your current merge for a week, compare normalized records and the report, and keep the old step as your exit path. See the migration checklist and documented limits.

For the same two inputs, create separate outputs with both tools:

lcov --branch-coverage --function-coverage -a coverage/shard-a.info -a coverage/shard-b.info -o coverage/lcov.info
lcovmerge coverage/shard-a.info coverage/shard-b.info -o coverage/lcovmerge.info --strict-checksum

Compare normalized records and the reports produced from both files; a plain text diff is not a semantic compatibility check.

Paths and input lists

Rebase paths, filter inputs, or use a list file

Rebase source paths

Use --rebase when SF: paths point to a build directory but reports use another root.

lcovmerge --rebase /build/worker/project=/workspace/project shard-a.info shard-b.info -o merged.info

A path below /build/worker/project is rewritten below /workspace/project. Check emitted paths against the source tree used by your report generator.

Use a list file

lcovmerge @coverage-files.txt -o merged.info

A list file has one input path per line. Blank lines and lines beginning with # are ignored. Paths are relative to the current working directory; nested list files are limited to eight levels. The shell expands globs; lcovmerge does not.

Advanced options

Command-line options in lcovmerge 1.0.2
OptionPurpose
-o, --output FILERequired. Write to FILE, replacing it only after a successful merge. Use - for standard output.
--mem-limit SIZELimit memory reserved for coverage records. Total process memory can be higher, and sorting uses temporary disk. Default 64M; minimum 8M per job. Bare values are bytes; K, M, and G suffixes are binary multiples of 1024.
--tmpdir DIRWrite sorted batches to temporary files in DIR before merging them. The directory must exist and have enough free disk space. Files are removed after success and handled failures; caught POSIX SIGINT, SIGTERM, and SIGHUP also trigger cleanup. SIGKILL or machine failure can leave files. Windows interruption cleanup is not guaranteed. Default: the system temporary directory.
-j, --jobs NUse 1–32 workers to write sorted batches to temporary files before merging them. The default is min(4, detected cores), reduced if needed to fit the memory limit; explicit jobs require at least 8M per job. One large input file is not split across parser workers.
--prefix-strip PREFIXRemove a matching leading SF: source path prefix at a path boundary.
--rebase OLD=NEWRewrite a matching leading SF: source path prefix. Repeatable; matching is at a path boundary.
--include GLOBKeep a source path matching at least one include pattern. Repeatable; supports *, ?, and bracket ranges.
--exclude GLOBDrop matching source paths. Repeatable; exclusions take precedence over includes.
--branch-coverage on|offKeep or drop BRDA: rows. Default: on; this does not create branch data that is absent.
--no-function-dataDrop FN, FNDA, FNL, and FNA records.
--strict-checksumReturn status 2 when non-empty checksums for the same source line differ.
--warn-unknownPrint a diagnostic for each preserved unknown colon-delimited row inside a source section.
-qSuppress routine progress output; errors remain visible.
-vPrint parsed byte and record totals, selected worker count, and merged summary totals to standard error.
--statsPrint merged LF, LH, FNF, FNH, BRF, and BRH totals to standard error.
--versionPrint the version and build's Git commit identifier.
-h, --helpPrint the built-in usage summary.

CI and reporting recipes

Use these recipes after test jobs have exported LCOV files:

  • GitHub Actions · upload shard files, then merge them in a final job.
  • GitLab CI · collect artifacts and merge after test jobs finish.
  • Jenkins · merge files produced by parallel stages.
  • CMake with gcov · capture LCOV, then merge independent outputs.
  • Bazel · use only when a separate LCOV merge is still needed.
  • Report and upload consumers · pass the merged file to an LCOV-aware tool.
