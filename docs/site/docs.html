Usage guide

Install and merge LCOV .info files.

Quick start, release downloads, command options, path handling, and recipes for common CI jobs.

Quick start and install

Use lcovmerge after your collector has written LCOV files. The release page has archives for Linux, macOS, and Windows.

lcovmerge coverage/shard-*.info -o coverage/merged.info
genhtml coverage/merged.info --output-directory coverage/html
lcovmerge --version

The output remains LCOV for your report or upload step. Download v1.0.1.

Linux · x86-64

For Linux ARM64, select its matching archive from the release page.

set -eu
asset=lcovmerge-1.0.1-linux-x86_64.tar.gz
base=https://github.com/megasoft1978/lcovmerge/releases/download/v1.0.1
curl -fL "$base/$asset" -o "$asset"
curl -fL "$base/SHA256SUMS" -o SHA256SUMS
grep " $asset$" SHA256SUMS | sha256sum -c -
tar -xzf "$asset"
./lcovmerge --version

macOS · Apple silicon or Intel

set -eu
base=https://github.com/megasoft1978/lcovmerge/releases/download/v1.0.1
case "$(uname -m)" in
  arm64|aarch64) asset=lcovmerge-1.0.1-macos-arm64.tar.gz ;;
  x86_64|amd64) asset=lcovmerge-1.0.1-macos-x86_64.tar.gz ;;
  *) echo "Unsupported Mac architecture: $(uname -m)" >&2; exit 1 ;;
esac
curl -fL "$base/$asset" -o "$asset"
curl -fL "$base/SHA256SUMS" -o SHA256SUMS
grep " $asset$" SHA256SUMS | shasum -a 256 -c -
tar -xzf "$asset"
./lcovmerge --version

Windows · CI-verified only

Windows runtime behavior has not been verified on a Windows host.

$asset = "lcovmerge-1.0.1-windows-x86_64.zip"
$base = "https://github.com/megasoft1978/lcovmerge/releases/download/v1.0.1"
Invoke-WebRequest "$base/$asset" -OutFile $asset
Invoke-WebRequest "$base/SHA256SUMS" -OutFile SHA256SUMS
$entry = Get-Content SHA256SUMS | Where-Object { ($_ -split '\s+', 2)[1].TrimStart('*') -eq $asset }
if (@($entry).Count -ne 1) { throw "Expected one checksum entry for $asset" }
$expected = ($entry -split '\s+', 2)[0].ToLowerInvariant()
$actual = (Get-FileHash -Algorithm SHA256 $asset).Hash.ToLowerInvariant()
if ($actual -ne $expected) { throw "SHA256 checksum mismatch" }
Expand-Archive $asset -DestinationPath .\lcovmerge
.\lcovmerge\lcovmerge.exe --version

Common and full options

  • -o FILE writes one LCOV file after a successful merge.
  • --mem-limit SIZE sets memory reserved for coverage records; total process memory can be higher.
  • --tmpdir DIR selects where sorted batches are written before they are merged. The directory must exist and have free disk space.
  • -j N sets workers that write sorted batches to temporary files before merging; one large input file is not split across parser workers.

Paths and input lists

Rebase source paths

Use --rebase when SF: source paths point to a build directory but reports use another root.

lcovmerge --rebase /build/worker/project=/workspace/project shard-a.info shard-b.info -o merged.info

A path below /build/worker/project is rewritten below /workspace/project. Check the resulting SF: paths against the source tree used by your report generator. Rewriting is not automatic path detection.

Strip a path prefix

--prefix-strip PREFIX removes a matching leading source-path prefix at a path boundary. Rewriting runs in this order: --rebase, --prefix-strip, then include and exclude filters. If two paths become identical, their records are merged.

Use a list file

lcovmerge @coverage-files.txt -o merged.info

A list file has one input path per line. Blank lines and lines beginning with # are ignored. Paths are relative to the current working directory; nested list files are limited to eight levels. Use @@name for a literal path that begins with @. The shell expands globs; lcovmerge does not.

Compatibility and exit codes

What lcovmerge reads and writes

lcovmerge reads existing LCOV .info files. It does not collect raw coverage or generate reports. If a report tool accepts all shard files directly, you may not need a separate merge.

--mem-limit limits memory reserved for coverage records; total process memory can be higher. Sorting writes batches to temporary files and merges them, so the selected directory needs free disk space. Output order is stable for the same inputs, options, and build across input order and worker settings; this does not promise byte-for-byte identity with LCOV. Unknown colon-delimited rows are preserved, not interpreted; their application-specific merge meaning is unknown. lcovmerge is not a drop-in replacement for lcov -a; compare your records and report using the migration guide and limits.

Exit codes

CodeMeaning
0Success.
1Invalid or incomplete command-line options.
2Input or LCOV .info format error, including strict checksum disagreement.
3Input/output or temporary-file I/O failure, allocation failure, or interruption.

CI, build, and report recipes

Each recipe uses LCOV files that have already been exported.

  • GitHub Actions · upload shard files, then merge them in a final job.
  • GitLab CI · collect artifacts and merge after test jobs finish.
  • Jenkins · merge files produced by parallel stages.
  • CMake with gcov · capture LCOV, then merge independent outputs.
  • Bazel · use only when a separate LCOV merge is still needed.
  • Report and upload consumers · pass the merged .info file to an LCOV-aware tool.
