LCOV files · one merge step · C11

Many files.
One LCOV file.

LCOV .info files are text reports of which source lines, functions, and branches your tests ran. lcovmerge combines the files your test jobs already export, so the next step can read one file.

A quick fit check

Does your pipeline need a merge step?

+ Use lcovmerge when

Test jobs already export LCOV .info files, and a later report or upload step needs one file.

↗ Skip it when

  • Your consumer accepts every shard directly.
  • Your LLVM, Go, Python, or JavaScript tools can merge their native coverage data before export.
  • Codecov or Coveralls already combines your uploads.
  • Your files are small and lcov -a is fast enough.

lcovmerge starts with existing LCOV files. It does not read raw .gcda or .profraw data, collect coverage, or generate an HTML report.

The handoff

Parallel tests. One final merge job.

Each test job uploads one uniquely named artifact. The last job downloads those files, merges them, and passes the result to your report step.

coverage.ymlmatrix upload → merge → report
name: coverage

on: [push, pull_request]

jobs:
  test-shard:
    runs-on: ubuntu-latest
    strategy:
      matrix:
        shard: [unit, integration]
    steps:
      - uses: actions/checkout@v7
      - run: ./ci/export-lcov.sh "${{ matrix.shard }}"
      - uses: actions/upload-artifact@v7
        with:
          name: coverage-${{ matrix.shard }}
          path: coverage/${{ matrix.shard }}.info

  merge:
    needs: test-shard
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7
      - uses: actions/download-artifact@v8
        with:
          pattern: coverage-*
          path: coverage/shards
          merge-multiple: true
      - name: Merge LCOV shards
        uses: megasoft1978/lcovmerge@v1.0.2
        with:
          files: coverage/shards/*.info
          output: coverage/merged.info
          mem-limit: 256M
      - uses: actions/upload-artifact@v7
        with:
          name: merged-coverage
          path: coverage/merged.info
      - run: genhtml coverage/merged.info --output-directory coverage/html

The exporter command is a placeholder for yours. This example uses the v1.0.2 tag; pin the Action to its full commit SHA if your policy requires immutable refs.

Shellfrom the job that has the shards
lcovmerge coverage/shards/*.info -o coverage/merged.info
genhtml coverage/merged.info --output-directory coverage/html

Your shell expands *.info before it starts lcovmerge. The program does not expand wildcards itself.

Try it beside your current merge

Keep a clear way back.

For a week, run lcovmerge in a non-blocking CI job against the same shards. Compare normalized records and the report from your current consumer; keep the old merge as the exit path until the differences are accepted.

lcovmerge coverage/shards/*.info -o coverage/lcovmerge.info
lcov --summary coverage/current.info
lcov --summary coverage/lcovmerge.info

These summaries are a quick report check, not a full semantic comparison. For normalized record checks and the rollout checklist, see the migration guide.

Get the binary

Install and verify v1.0.2.

Linux and macOS release binaries are available. The Windows archive is available; runtime verification on a Windows host is pending.

Each command checks the downloaded archive against the published SHA256SUMS file before extraction.

Linux · x86-64

For Linux ARM64, choose its matching archive from the release page.

set -eu
asset=lcovmerge-1.0.2-linux-x86_64.tar.gz
base=https://github.com/megasoft1978/lcovmerge/releases/download/v1.0.2
curl -fL "$base/$asset" -o "$asset"
curl -fL "$base/SHA256SUMS" -o SHA256SUMS
awk -v name="$asset" '$2 == name || $2 == ("*" name) { count++; print } END { if (count != 1) exit 1 }' SHA256SUMS > "$asset.sha256"
sha256sum -c "$asset.sha256"
tar -xzf "$asset"
./lcovmerge --version

macOS · Apple silicon or Intel

set -eu
base=https://github.com/megasoft1978/lcovmerge/releases/download/v1.0.2
case "$(uname -m)" in
  arm64|aarch64) asset=lcovmerge-1.0.2-macos-arm64.tar.gz ;;
  x86_64|amd64) asset=lcovmerge-1.0.2-macos-x86_64.tar.gz ;;
  *) echo "Unsupported Mac architecture: $(uname -m)" >&2; exit 1 ;;
esac
curl -fL "$base/$asset" -o "$asset"
curl -fL "$base/SHA256SUMS" -o SHA256SUMS
awk -v name="$asset" '$2 == name || $2 == ("*" name) { count++; print } END { if (count != 1) exit 1 }' SHA256SUMS > "$asset.sha256"
shasum -a 256 -c "$asset.sha256"
tar -xzf "$asset"
./lcovmerge --version

Windows · runtime verification pending

The release archive is available. A cross-built executable and CI tests are not a Windows-host runtime check.

$asset = "lcovmerge-1.0.2-windows-x86_64.zip"
$base = "https://github.com/megasoft1978/lcovmerge/releases/download/v1.0.2"
Invoke-WebRequest "$base/$asset" -OutFile $asset
Invoke-WebRequest "$base/SHA256SUMS" -OutFile SHA256SUMS
$entry = Get-Content SHA256SUMS | Where-Object { ($_ -split '\s+', 2)[1].TrimStart('*') -eq $asset }
if (@($entry).Count -ne 1) { throw "Expected one checksum entry for $asset" }
$expected = ($entry -split '\s+', 2)[0].ToLowerInvariant()
$actual = (Get-FileHash -Algorithm SHA256 $asset).Hash.ToLowerInvariant()
if ($actual -ne $expected) { throw "SHA256 checksum mismatch" }
Expand-Archive $asset -DestinationPath .\lcovmerge
.\lcovmerge\lcovmerge.exe --version

Other paths: Homebrew tap, Scoop, Docker, build from source, or the GitHub Action.

Know the boundaries

A small merger with clear edges.

Memory and scratch space

--mem-limit limits memory reserved for coverage records. Total process memory can be higher. Sorting writes temporary files, so allow disk space in a writable --tmpdir.

LCOV policy differences

Output is not byte-for-byte identical to LCOV and lcovmerge is not a drop-in for lcov -a. Compare records and reports before switching. See the compatibility notes.

Files and platforms

Input must already be LCOV .info. One large input file is not split across parser workers. Windows runtime verification is pending a Windows-host run.

First-run recovery

Common errors, one next step.

  • Exit 1 · options: check spelling and required values with lcovmerge --help.
  • Exit 2 · input or format: open the named .info file at the reported line and fix the malformed row.
  • Exit 3 · I/O, allocation, or interruption: fix output or --tmpdir access, free scratch space, or lower --jobs if allocation failed.
  • No inputs matched: confirm the artifact download path; the shell expands *.info before lcovmerge runs.
